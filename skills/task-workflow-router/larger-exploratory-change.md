# Larger Exploratory Change

Use this mode when the user is exploring a larger change, making architectural decisions, or preparing work for later execution.

## Workflow

1. Use `exploratory-context-gathering` to gather evidence from the codebase.
2. Use `architecture-design` to compare options, name boundaries, and lock important decisions.
3. Use `create-specification` after direction is approved.
4. Use `style-coding-guidelines` during implementation.
5. Use `verification` to choose and run concrete checks.
6. Use `review` before final reporting.
7. Use `post-task-capture` to identify docs, skill, rule, or repo-local knowledge follow-ups.

## Rules

- Do not jump from vague intent to implementation.
- Do not write a spec before the main decisions are clear.
- Keep open questions visible instead of hiding uncertainty behind flexible wording.
- If the work becomes small and obvious, collapse to the minor known change workflow.
