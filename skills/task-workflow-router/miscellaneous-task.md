# Miscellaneous Task

Use this mode when the request does not clearly fit repo-knowledge lookup, minor known change, or larger exploratory change.

## Instructions

1. Handle the request directly if it is simple.
2. Check whether a phase skill applies before doing substantial work.
3. Ask for classification only when the choice would materially change the workflow.
4. Keep the response proportional to the task.

## Common Routes

- Debugging with unclear cause: start with exploration, then verification.
- Code review: use `review`.
- Cleanup request: use `refactoring-cleanup`.
- Test or CI request: use `verification`.
- Planning request: use `architecture-design` or `create-specification`.
